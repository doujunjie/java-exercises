# 第6章 方法与递归

## 本章知识点

- 方法定义包含访问修饰符、返回值类型、方法名、参数列表和方法体；`void` 表示不返回值。
- `return` 用于返回结果并立即结束方法；有返回值的方法所有分支都必须能返回。
- 调用方法时传入的是实参，方法定义中的是形参，二者按位置一一对应，类型要兼容。
- Java 只有值传递：基本类型传值，引用类型传引用的副本，但通过引用仍可修改对象内容。
- 方法重载：同一个类中方法名相同、参数列表不同；返回值类型不同不构成重载。
- 递归必须同时具备递归出口和向出口靠近的递归关系，否则会无限递归直到 `StackOverflowError`。
- 递归适合天然分治的问题（阶乘、斐波那契、树的遍历），但可能重复计算子问题。
- 迭代通常用循环和若干状态变量从前往后推，效率高、不占用调用栈。
- `long` 比 `int` 范围大，阶乘、斐波那契等增长很快的数列应优先使用 `long`。
- 参数非法时可以抛出 `IllegalArgumentException`，让错误尽早暴露。
- 易错点一：递归忘记写出口，或出口条件永远不成立，会栈溢出。
- 易错点二：只修改返回值类型来“重载”方法，编译器会报方法重复定义。
- 易错点三：递归计算斐波那契时 n 稍大就非常慢，因为同一个子问题被重复计算了指数级次数。

## 进阶挑战

1. 汉诺塔：把 n 个盘子从 A 柱借助 B 柱移到 C 柱，每次只能移动一个且大盘不能压在小盘上，用递归打印每一步移动，并统计移动次数。
2. 带记忆化的斐波那契：用一个 `long[] memo` 保存已经算过的结果，比较它与朴素递归在 n = 45 时的耗时差异，理解“空间换时间”。

## 怎么运行

1. 在 IntelliJ IDEA 中打开本项目，进入 `src/ch06_methods` 目录。
2. 打开任意练习文件，点击 `main` 方法左侧的绿色三角，选择 Run 即可运行自检。
3. 参考答案在 `solutions/ch06_methods` 目录下的同名文件中，重点看递归出口、重载判定和两种斐波那契写法的对比。
4. 也可以在项目根目录执行 `javac -encoding UTF-8 -d out src/ch06_methods/*.java`，再执行 `java -cp out ch06_methods.Ex03Fibonacci`。
